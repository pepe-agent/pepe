# Release Notes 0.10.1

Hi! Here's what's new, improved, and fixed for security in this Pepe update.

---

## ✨ What's New

### Browser tool: drive a real Chrome

Your agent can now open a real browser to reach pages that need JavaScript, log in, or walk through a multi-step flow. One session per conversation, cookies and the current page persist from one call to the next until you close it or leave it idle for 10 minutes. Page elements (buttons, inputs, links) get numbers the agent uses to click, instead of guessing CSS selectors.

Pepe looks for Chrome, Chromium, Edge, or Brave already on the machine; if it can't find one, it downloads one automatically and caches it (turn that off with `PEPE_BROWSER_AUTO_DOWNLOAD=0` if you'd rather it didn't). Works out of the box on Docker, macOS, and Windows. On Linux ARM (Apple Silicon, ARM64 cloud hosts), it pulls from Playwright's CDN.

Same protections `fetch_url` already has: only `http://` and `https://`, internal addresses (`localhost`, private networks) are blocked. And it's gated like `bash`, never always-allowed by default.

📍 *Where to use it: chat or dashboard, add the `browser` tool to the agent*

### memory_search: search your own memory

Your agent can now search its own memory (`MEMORY.md`, `USER.md`, `people.md`) without reading the whole file. Simple case-insensitive search, fast and direct, no embeddings, because memory is kept small on purpose (the consolidation pass does that job).

Always safe, and it only reaches the memory of the agent making the call.

📍 *Where to use it: any agent with memory can use it*

### session_search: find past conversations

There's now a tool to search and read past conversations, they no longer disappear once the session ends or Pepe restarts. Available actions: list sessions, search by content, view a conversation's full history, show a specific turn.

Always safe, and each agent only sees its own conversations, not other agents' in the same company or project.

📍 *Where to use it: chat or dashboard, add the `session_search` tool to the agent*

### mix pepe flow: promote a proven sequence into a script

When your agent runs the same sequence of tool calls two or more times (say, "validate the data, save it to the database, send an email"), you can promote that into a script that runs without calling the model. Useful for repetitive or scheduled automations.

`mix pepe flow promote NAME` proposes the script; `mix pepe flow run NAME` runs it on demand; `mix pepe flow schedule ...` schedules it to run on its own (cron). A flow only runs steps that already passed the agent's `auto_approve`, so it never needs human approval mid-run.

📍 *Where to use it: CLI, `mix pepe flow --help`*

### See your agent's full prompt

`mix pepe agent prompt NAME` now shows exactly what the model sees as its system prompt, not just the `system_prompt` field, but everything (persona, behavior contract, date and time, skills/docs index, everything Pepe assembles). There's an "Assembled prompt" view in the dashboard too.

Useful for debugging unexpected behavior or understanding what your agent actually knows.

📍 *Where to use it: CLI (`mix pepe agent prompt NAME`) or the dashboard's agent page*

### fetch_url now extracts readable text

`fetch_url` used to return raw HTML, navbars, cookie banners, and ads included. Now it returns the page's readable text by default, it skips known noise elements, prefers `<article>` or `<main>`, and falls back to scoring heuristics if neither exists.

If you need the literal HTML (a JSON response, source code), use `raw: true`. Pages with nothing extractable fall back to raw automatically.

📍 *Where to use it: automatically in `fetch_url`, no action needed*

### mix pepe browser install: use the system's own Chrome

On Linux, instead of always downloading Chrome, `mix pepe browser install` detects your package manager (apt, dnf, pacman, brew) and installs a real one on the machine, asking for `sudo` when needed. Once installed, `browser` uses it directly with no download.

Linux only; on macOS and Windows, Pepe already does the right thing, no action needed.

📍 *Where to use it: CLI, `mix pepe browser install`*

### Commitments: track reminders and promises

New opt-in feature (off by default): when someone asks "remind me in a week" or the agent promises "I'll check on this tomorrow," Pepe notes it automatically at the end of the turn and tracks it.

A reminder from the user delivers a ready message once it's due. A promise from the agent re-runs the session, so the work actually happens before it says it's done.

Manage it from the conversation with the `commitment` tool, or from the new **Commitments** page in the dashboard.

📍 *Where to use it: dashboard's **Commitments** page, or chat with the `commitment` tool*

### ask_user: ask real questions

New `ask_user` tool for asking a genuine multiple-choice question, tappable buttons on Telegram, an arrow-key menu in the console, a picker in the dashboard. It blocks and returns the answer in the same turn, instead of ending the conversation and hoping the next message happens to answer it.

Never gated (asking carries no risk), but it only works where there's an interactive person, it fails immediately on a webhook or cron.

📍 *Where to use it: agents that need a concrete answer from the user*

### delegate with background: true, fire and let it run

`delegate` now accepts `background: true` to fire off a job without waiting, it returns a message right away and the results arrive later as a follow-up, instead of blocking the conversation for up to 3 minutes.

📍 *Where to use it: whenever you want asynchronous delegation*

### Telegram: polls and quick_reactions

- New `telegram_poll` tool posts a real poll on Telegram (quiz polls included).
- New `quick_reactions`: a message that's just a "thanks" or an emoji gets a native reaction instead of a full reply (no model call).

📍 *Where to use it: Telegram, configure it on the agent or use the poll tool*

## 🚀 Improvements

### Board card heartbeat: a sign of life for long jobs

A card that was genuinely being worked on, past its `claim_timeout_s`, had no way to say "hey, I'm still here," it could get flagged as stuck even while alive. New `board heartbeat` (and `mix pepe board card heartbeat ID`) resets the clock without changing status, a pure sign of life, not progress.

📍 *Where to use it: dashboard or CLI*

### bash/run_script are quieter for safe commands

An `ls`, `cat`, `git status`, or `pytest` now runs directly with no approval prompt, the same free pass `read_file` already had, because there's no risk. Commands that touch files, delete things, or reach the network still ask as before. This only changes on interactive surfaces (chat, dashboard); on a webhook, cron, or API with no human, nothing changes.

📍 *Where to use it: automatic*

### mix pepe update points at the changelog

After an update, `mix pepe update` now shows where to look for what changed (CHANGELOG.md and `mix pepe agent prompt NAME`). Useful because each agent's system prompt genuinely changed and there's nothing in `config.json` to diff.

📍 *Where to use it: automatic*

### Database migrated to SQLite

Commitments, the config journal, watches, traces, boards, and usage moved out of `config.json` and loose files into an embedded SQLite database (`~/.pepe/data/pepe.db`). Faster, more robust, no breakage on any surface, the public APIs (`Pepe.Config.commitment_*`, etc.) stay the same.

Agent, model, and channel definitions stay in `config.json` as before (editable, git-diffable, portable).

📍 *Where to use it: automatic, nothing to do*

## 🐛 Security and Reliability Fixes

### Browser: any request pointing inward is now blocked

The browser had SSRF protection on the initial URL (`open`), but links the page itself clicked, JS redirects, form submits, and the page's own fetch/XHR calls slipped through unnoticed. Everything now goes through interception (CDP Fetch domain), validated the same way `open` already is, if it resolves to an internal address, it fails before Chrome ever sends anything.

### session_search: now only sees your own conversation by default

If an agent serves several customers in the same project (a support bot, say), searching past conversations could leak one customer's history to another. The default is now `"self"`, each conversation only sees itself. An agent that genuinely has no other customer to leak to can opt in via the `session_search_scope` setting (a checkbox in the dashboard) to see the whole project.

### run_script in python/node/ruby now asks for approval

Python, Node.js, and Ruby had the same free pass `bash` gets (no apparent risk, runs directly), but the risk analyzer only understands shell syntax, a Python one-liner that deletes files or opens a socket ran with no warning. Now only `bash`/`sh` get the free pass. And the shell analyzer gained detection for `find -delete`, `dd`, `mv`/`cp`/`chmod`, relative redirects, and piping in any interpreter.

### send_to_agent preserves the calling conversation's context

`send_to_agent` runs a nested consult inside the calling turn's own process, starting that without care reset the turn's taint and grant state. It now takes a snapshot first, runs the nested call, and restores afterward.

### An invisible character in the middle of a token no longer slips through

A `<|im_start|>` with a zero-width space in the middle escaped control-token sanitization, the two passes ran in the wrong order. Fixed.

### Flow.replay stops on errors, not just on denials

A step that errored out (a missing file, a dropped network connection, bad arguments) let every step after it keep running anyway, and the flow was reported as "complete." It now stops at the first step that fails, exactly as it already did for denials.

### Promoting a flow now checks for a clean run

Promoting a flow from traces could bake in a tool call that had been denied or had failed at the source (the event is recorded before the outcome is known), or compare truncated arguments against the real ones. It now refuses any trace that isn't clean: no denied or failed calls, and nothing truncated.

### Flow bindings survive a rename

Renaming an agent or its project never updated the flows that agent owned, a scheduled flow would break for good. Fixed (the same kind of gap already closed for traces, usage, and watches).

### A raw model connection (no agent) no longer receives an agent's system prompt

A `/v1/chat/completions` call with just `model: <name>` (no agent) started receiving the agent's full prompt (contract, docs, everything) instead of the plain seed. It was a side effect of a prompt-parity fix that hadn't accounted for that internal wrapper. Fixed.

### Stale browser ref tags no longer collide with new elements

An old `data-pepe-ref` tag from a previous snapshot could collide with a different element in the new one, so "click ref 3" would hit whatever was #3 on the page now. Every snapshot now clears old refs before relabeling.

### Browser on Windows always downloaded the 32-bit build

`:erlang.system_info(:system_architecture)` returns the literal string `"win32"` on Windows even on 64-bit CPUs. It now reads Windows's own `PROCESSOR_ARCHITECTURE`/`PROCESSOR_ARCHITEW6432` environment variables instead.

### mix pepe browser install works on Ubuntu

`apt chromium` there is a transitional stub with no installable candidate (the real package is Debian's). It now tries `chromium-browser` (Ubuntu's actual package) as a fallback. Fixed.

### Browser timeouts and crashes now report clearly

A `browser` call after a timeout or a real crash used to be misreported as "no open session," the same message as a normal close race. It now says clearly what happened.

### Telegram: files over 20MB no longer disappear silently

A Telegram file over 20MB (the bot's limit) used to vanish with no complaint. It now names the reason ("file too large for the bot to fetch"), and in a multi-file upload, it tells you which ones didn't arrive.

### Board heartbeat no longer breaks dead-worker detection

`board heartbeat` was resetting `claimed_at`, the column the scheduler uses for stuck-worker detection (`block_if_still_running/3`). A heartbeat during a long dispatch invalidated that safety check. Heartbeat now writes to its own separate `heartbeated_at` column.

### Board race conditions closed

Card operations (claim, complete, block, and so on) and board deletion had race windows: cleanup could hit a card that had just been claimed, a caller could get back `nil`, deleting an empty board could cascade into a card created at that exact moment. Every check and its write are now one atomic step.

### Commitments/watches no longer orphaned after an agent is deleted

Deleting an agent used to leave behind any commitment or watch tied to it through a never-resolved handle reference (an orphaned reference). It now removes those along with the rest of the agent's bindings.

### A failed trace is now logged

A trace that failed to save (a database hiccup) used to disappear silently. It's now logged as a warning, the same tolerance the config journal already has.
