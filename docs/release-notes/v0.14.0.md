# Release Notes 0.14.0

Hi! Here's what's new and improved in this Pepe update.

---

## ✨ What's New

### The dashboard password is now protected in the config file

Until now, the password you set for Pepe's dashboard was stored in plain text in `config.json`. Anyone with access to the file could read the password directly. It's now encrypted (bcrypt hash), much more secure. If you already have an old password stored in plain text, the system still accepts it, but the next time you set a new one, it'll be protected from the start.

📍 *Where to see it: `pepe dashboard password` (CLI) or the Settings → Dashboard page*

### You now type the dashboard password without it showing on screen

When you run `pepe dashboard password` in the terminal, the password is now entered "hidden," the secure way where the characters don't show up as you type. Before, the password had to come in as a command argument (`pepe dashboard password 'my_password'`), which left it visible in the terminal history of anyone who used that machine. Now it's safer: you type it and it never appears.

📍 *Where to see it: the server terminal, `pepe dashboard password` command*

### New CLI reference page on the website

We built a reference page listing every `pepe` command, now organized by topic (configuration, models, agents, running, Telegram, and so on), with usage examples, in Portuguese and English. Before, you had to hunt for commands scattered across several documentation pages.

📍 *Where to see it: website, Documentation → CLI Reference*

### Agent pages can now connect to specific extensions

If you use Pepe plugins (extensions), you can now say "this agent should use this specific plugin for memory search" or "for web search," directly in the dashboard, no need to edit the config file by hand. Before, this was only possible by editing it manually.

📍 *Where to see it: Dashboard → Agents → (open an agent) → "Extension slots" section*

---

## 🚀 Improvements

### If you run Pepe in a Docker container, you now get the right instructions

When the dashboard showed an error or wanted to teach you a command, it sometimes suggested `mix pepe ...`, which is a development-only command that doesn't work inside a container. This confused anyone genuinely running Pepe in Docker. The instructions are now different: inside a container, the system suggests the command that actually works there (`bin/pepe rpc`).

📍 *Where to see it: any error message or instruction in the dashboard*

### The Settings screen no longer gets squeezed by lots of history

When you had many recent changes to your configuration, the history list took up so much space that the `config.json` editor became tiny and nearly unusable. The history now gets its own space (with its own scrollbar), so the editor stays visible and usable.

📍 *Where to see it: Dashboard → Settings*

### Dashboard text is more direct and clear

We rewrote the dashboard's longer instructions (the text explaining what each button does, what each option means) to be more direct. All the security details are still there, just explained better and with less roundabout phrasing.

📍 *Where to see it: every form and section in the dashboard*

---

## 🔧 Fixes

### The terminal no longer freezes when a prompt has no input

If you ran `pepe setup` or `pepe model add` in the terminal and closed the input connection (say, by closing the tab, disconnecting SSH, or piping from a file that ran out), the command got stuck in an infinite loop, burning 100% CPU. It now warns and exits cleanly.

### Quick commands no longer break when you have plugins installed

If you wanted to run a command like `pepe agent add ...` or `pepe plugin route enable ...` (ones that change configuration without starting the whole server) and you had plugins installed, Pepe would simply crash. It now works fine.

### Unknown slot names are now rejected

If you typed a slot name wrong (a typo) in the agent editor or via the CLI, Pepe silently accepted it and did nothing. It now complains and tells you what's wrong.

### Dashboard translations fixed

The word "not installed" had been mistranslated into Portuguese (it said "not allowed"). It's now correct in both European and Brazilian Portuguese.

---

## 🛡️ Security

### Dependency update closing a security flaw

We updated the `postgrex` library (0.22.3 → 0.22.4), which had a SQL injection flaw. Pepe itself isn't directly affected (it doesn't use that feature), but the update is good security practice and is included in this release.

📍 *Technical details: GHSA-3gww-3f36-2388 / CVE-2026-66838*
