# Release Notes 0.21.0

Settings for each channel, pick people instead of typing ids, safer restarts, and a Slack that reads and sends files.

---

## ✨ What's new

### Each channel, tuned on its own

On the Channels page, every connection now shows how many channels it has heard from and lists them: Slack channels (public and private), direct messages, Discord, Teams and Google Chat spaces, and Telegram groups and topics. Each one has its own agent, its own mention rule and its own list of who can train it, and each value says whether it is the channel's own or comes from the connection, with a button to go back to the connection's. The connection holds the default; a channel can differ.

📍 *Where to find it: Channels, then the "N channels" line on a connection*

### Pick people, not ids

Anywhere you used to type user ids, you now pick from the people who have written: who can train, who may message a connection, who can train a Telegram bot. Names come first, ordered by name; people without a name follow, latest message first. A small field still lets you add someone who has not written yet. Pepe remembers who wrote (id and display name) per channel, and deleting the connection removes them.

Connections, bots, channels and people can also have a label, shown wherever their id would be, so `A0C5LM7LHS8` can read "Customer support".

📍 *Where to find it: Channels, the pencil next to any name*

### Mention rules that make sense

- A connection can answer every channel without an @mention, and a single channel can go the other way. The conversation's own `/mention`, then the channel, then the connection, then "a mention is required".
- In a channel that answers without a mention, a message that tags someone else (and not the bot) is for them, so the bot stays out of it.
- An app you list in a connection (a help desk posting each new ticket, for example) is answered on its own, while people in the same channel still have to mention the bot.
- `/trainers` sets who may train one channel, from the chat. Only someone who can train it now may change it.

📍 *Where to find it: Channels, and `/mention` and `/trainers` in any channel*

### Slack reads and sends files, and shows it is working

Pictures, files and the coloured-bar attachments other apps post are now read. Files the agent generates reach Slack again (Slack retired the old upload). While the agent works, the message gets an eyes reaction, and a 👍, ❤️ or 👎 on one of its messages reaches the agent as feedback.

📍 *Where to find it: add the `files:read`, `files:write` and `reactions:*` scopes to the Slack app*

### Ask for permission in the chat

On a webhook channel (Slack, Teams, Google Chat, Discord, WhatsApp), a risky action that is not pre-approved can now be settled right in the conversation by typing allow or deny, instead of waiting for someone to approve it on the command line. Turn it on by naming who may answer.

### Restarts no longer lose messages

When Pepe shuts down for an update, it now stops taking new work immediately: an API request gets a "try again" answer, Slack, WhatsApp and the others resend the message after the restart, the Telegram poller steps aside so nothing is dropped, and the conversations already running get up to 25 seconds to finish.

### `/learn` tells you when it is done

It used to say "Reviewing what I learned..." and go quiet. Now it follows up with what was saved, or that there was nothing new, or that it could not finish.

### Leaner prompts, smarter habits

Agents no longer receive instructions that cannot matter in their conversation: a dashboard or API chat is about 13% smaller, and an API agent with few tools about 23%. Two habits were added for every agent: use the documented way before saying a system cannot be reached, and fix a note that turns out to be stale.

### More, in short

- A decision-only model connection and a `decide` tool, for sorting messages cheaply with a normal model behind it.
- An opt-in `topic_reroute` option lets a conversation leave the wrong agent without `/new`.
- A built-in `pepe-help` skill tells an administrator where to do anything in Pepe.
- A plugin tool can say that what it returns was written by somebody else, so pre-approval stops applying after it.
- `end_session` no longer asks for approval, and `switch_agent` stops asking when its route already allows the handoff.

---

## 🐛 Fixes

- **A file the agent sends on Telegram no longer hangs and fails**, including images, spreadsheets and voice replies.
- **A call waiting for approval no longer tells someone in a chat to run a command on the server.**
- **A `/stop`, a `/new` or a crashed run no longer leaves a half-done "switch agent" or "end the conversation" behind.**
- **Counting a customer message no longer takes the conversation down** when the usage database is unavailable.
- **The reactions setting on a Slack connection reads in plain words** instead of showing `own` and `off`.
