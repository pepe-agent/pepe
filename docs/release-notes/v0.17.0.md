# Release Notes 0.17.0

A release focused on **Telegram groups**, **smarter permissions**, and **fewer distractions** when something isn't configured.

---

## ✨ What's New

### Two new permission options to let the agent work uninterrupted

When you allow the agent to use a tool, you now have more choices:

**"Allow everything for this task"** authorizes the agent to use any tool for the rest of this specific task, no more questions asked. If it needs to read a file, run a command, and fetch a page, all of that happens in one sequence, without you clicking three separate times. It expires as soon as the task finishes; the next message goes back to asking normally.

**"⚠️ Allow everything for this session"** goes further still: nothing gets asked again until you type `/new` or restart. Use it when you trust the agent completely, for now. It carries a warning icon (⚠️) right on the option itself, to make clear this is a bigger grant.

Both show up everywhere: on Telegram, on the dashboard, and on the command line.

📍 *Where to see it: any permission prompt*

---

## ⚡ Changes

### In a Telegram group, only the newest message shows who sent it

When several people talk in a Telegram group, the agent now knows exactly who spoke last, before, it could keep repeating the previous sender's name even after someone else had already replied.

The way the agent sees this changed too: before, every message carried the sender's name; from now on, only the current message carries it, in a way that doesn't get in the way of the rest of the conversation.

---

## 🔧 Improvements

### Langfuse now connects itself using credentials you already have

If you already set up trace export to Langfuse, things get simpler: Pepe now finds your `LANGFUSE_PUBLIC_KEY` and `LANGFUSE_SECRET_KEY` (the same ones you use for manageable prompts in Langfuse) and starts exporting traces automatically. No separate environment variables needed.

If you need to point at a different OTLP backend, the older variables (`OTEL_EXPORTER_OTLP_*`) still work and take priority.

---

## 🐛 Fixes

### The agent no longer complains about a missing credential when it just can't see it

When the agent checks a secret (an API key, a token) and finds it empty, it now knows the difference between:

- Empty because nobody ever configured it (a genuinely missing credential)
- Empty because you (the operator) deliberately hid it from the agent (the credential exists, it's just not visible to the agent)

Before, the agent assumed it was a missing credential in both cases and complained to the user. Now it only warns when something is actually missing.
