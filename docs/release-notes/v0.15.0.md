# Release Notes 0.15.0

A release focused on **learning and adapting**. Agents now learn from your reactions on Telegram, you can run the server on any network interface, compare models side by side, and execution traces now talk to Langfuse. Under the hood, plugin slots took over model selection and heartbeat pacing, and you have a new way to allow tools without approving them every single time.

---

## ✨ What's New

### Agents now learn when you react with 👍 or 👎 on Telegram

Every time you thumbs-up or thumbs-down (👍 or 👎) an agent's last message on Telegram, it notes that as feedback, what worked, what didn't, and remembers it in future conversations. It's continuous learning without you typing a word. A 👍 tells the agent "this worked, do it again." A 👎 tells it "avoid doing this again." The agent never replies to the reaction itself, it just learns from it.

📍 *How to use it: send an agent a message, tap 👍 or 👎 on Telegram*

### Compare models side by side with `mix pepe eval --models`

You can now run the same automated test against several models at once and see which one comes out ahead. List the models you want to test (`--models model-a,model-b,model-c`) and the result shows a pass/fail report for each one, without changing any agent's configuration.

```bash
mix pepe eval agent-boundaries --models model-a,model-b,model-c
```

📍 *Where to run it: terminal, `mix pepe eval`*

### New automated test suite: `agent-boundaries`

We built a test pack that checks whether your agents recognize what they CANNOT do: if you ask one to move real money, reach an agent that doesn't exist, or call a service that's down, the agent admits "I can't do that" instead of pretending it worked. It's an honesty guarantee.

📍 *Where to see it: `mix pepe eval agent-boundaries`*

### Execution traces now export to Langfuse (or any OTLP backend)

If you use Langfuse (or any system that speaks the OTLP protocol) to monitor your agents, Pepe now sends traces automatically: run time, tokens spent, which model was used, which tools were called, all of it. Just set one environment variable and it works. If the export fails for any reason, the conversation carries on as normal, the failure stays contained.

📍 *How to enable it: set `OTEL_EXPORTER_OTLP_ENDPOINT`*

### Agent persona manageable straight from Langfuse

You can now keep an agent's persona (its "voice") not in the config file, but in Langfuse, and edit it there without restarting Pepe. The change shows up within minutes. If Langfuse goes down, the agent falls back to its local persona automatically. It's opt-in for now: some agents have `langfuse_prompt` set, others keep reading from `config.json`.

📍 *How to use it: `mix pepe agent add NAME --langfuse-prompt PROMPT_NAME`*

### Prepaid balance for projects, a real brake for anyone charging customers

A project can now carry a credit balance (real funds, not just a monthly cap): `mix pepe project credit project-x 100.00` adds credit, `mix pepe project balance project-x` shows what's left. Once it hits zero, the agent refuses new calls until it's credited again. Unlike the monthly cap, which resets, this balance is actually spent down. A generic webhook lets your own payment system credit it automatically the moment a customer pays, no manual step needed on your end.

📍 *Where to see it: dashboard › Projects (a balance badge shows up once a project has ever been credited)*

### New permission option: "Allow with any parameters" for this session

Before, you had two choices: "yes to this exact command with these exact parameters" or "yes to any parameters of this command, forever." Now there's a middle ground: "yes to any parameters of this tool for the rest of this conversation," useful when you trust the agent right now but don't want a "forever" entry written into config. It shows up everywhere a permission is asked (Telegram, dashboard, terminal), and disappears once the conversation ends.

📍 *Where to see it: any permission prompt on Telegram or the dashboard*

### Plugin slots now cover "which model to use" and "when to call the assistant"

You can install a plugin that decides which model a given conversation uses (instead of it coming from the agent's own config), or one that decides whether the background assistant should act now or wait. Both used to be fixed code; now they're customizable extension points.

## ⚡ Changes

### Permission prompts got more serious: no more emojis

The text that asks for approval to run a tool (on Telegram, the dashboard, the terminal) is now more formal, no emojis, to make clear it's a real security decision, not casual chat.

### `mix pepe serve` now binds to localhost only by default

Before, `mix pepe serve` listened on every network interface (`0.0.0.0`), and with no authentication configured, that meant any machine on the network could call an AI API with no password. It now listens on `127.0.0.1` (your own machine) only by default. If you need to reach it from another machine on the network (or run it in a container behind a reverse proxy), use `--bind lan` to get the old behavior back.

📍 *If you need it: `mix pepe serve --bind lan`*

---

## 🐛 Fixes

### The agent no longer invents a fake text confirmation ritual

When a permission request expired unanswered, the agent used to try working around it by asking you to "type this magic phrase to confirm," which never worked, expired the same way, and repeated itself. The agent now knows the only way to get permission is by actually answering the real prompt (button or command), not typing made-up phrases.
