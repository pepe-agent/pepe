# Release Notes 0.18.0

A release focused on **installing skills with short names** and **richer traces in Langfuse**.

---

## ✨ What's New

### Install skills and plugins using PepeHub

Before, installing a skill or plugin meant pasting a long URL or remembering the exact file name. Now you can use short names straight from PepeHub, Pepe's skill and plugin marketplace.

**Two ways do the same thing:**
- `mix pepe skill install @handle/name`: use the short name
- `mix pepe skill install https://hub.pepe-agent.com/...`: or copy the URL from the page

If you get it wrong and try to install something as a plugin that's actually a skill (or the other way around), Pepe tells you which command to use instead.

All of this works because Pepe can now download and unpack `.zip` files even when the URL has no extension, exactly what PepeHub serves.

📍 *Where to find it: the terminal, with `mix pepe skill install` or `mix pepe plugin install`*

---

### Manage skills from the conversation with `manage_skill`

Before, only `manage_plugin` let you manage plugins from inside a conversation with the agent. Now there's an equivalent for skills: the `manage_skill` tool.

With it you can:
- **Search** the marketplace for skills
- **Install** a skill by short name or URL
- **Update** skills already installed
- **Remove** a skill you no longer need
- **Review** a skill before trusting it

It's exactly the same as `mix pepe skill ...` on the command line, just conversational: you ask the agent instead of running commands by hand.

📍 *Where to find it: while talking to an agent that has this tool enabled*

---

## ⚡ Changes

### Langfuse now gets a lot more context about every run

If you monitor your agents through Langfuse, the traces Pepe sends are much more informative now. Every run now includes:

- **Which channel it came from:** Telegram, API, or another
- **Who's running it:** the conversation's unique identifier (honestly labeled as chat-level, not per-person, on shared channels like Telegram groups)
- **Which version of Pepe was running** at the time
- **How it ended:** normal, warning, or error
- **How much each model call cost**, left out when we have no listed price for it, instead of showing a misleading zero

This makes debugging, measuring, and tuning your agents much easier: you see not just what happened, but for how much, from where, and how it ended.
