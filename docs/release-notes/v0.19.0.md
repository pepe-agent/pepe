# Release Notes 0.19.0

A release focused on **local machine learning**, **workflows with real logic**, and **multi-tool scripts in a single turn**.

---

## ✨ What's New

### Pepe.Insight: local machine learning on your own data

Pepe now has a subsystem that trains small models directly on data you already have, nothing sent out, no recurring API costs.

**How it works:** you define a question (for example, "will it rain tomorrow?" or "is this customer going to stay?"), point it at the historical data you already collect, and Pepe trains a compact model that answers that same question instantly from then on. Each call is essentially free; you only pay when you set it up or retrain it.

**What kind of question you can ask:**

- **Classification:** will it pass or fail? Approved or declined? Yes or no?
- **Number prediction:** how many units will sell? What's the expected value?
- **Trend over time:** how many admissions next month? Is growth accelerating?
- **Finding natural patterns:** what customer groups exist in the data? What's unusual about this new customer?

The algorithm is picked automatically as your data grows: with a few hundred rows, it uses something fast; with thousands, it switches to decision trees (the most robust choice for tabular data); with tens of thousands, it trains a more capable neural network.

**Not just numbers:** your text columns (like "subscription plan," "region," "product type") now work directly, Pepe encodes them automatically for you.

**Using it is easy:**
- Point it at a database connection you already have, or import data from a file or API
- Ask "analyze my data and suggest predictions": Pepe looks at your real tables and suggests what it can predict
- Confirm a suggestion (or describe your own), Pepe trains
- Ask for the result and get the answer instantly, at no AI cost at all

📍 *Where to find it: right in conversation with the agent, ask it to train or check a prediction*

### Pepe.Graph: workflows that correct themselves

You can now chain several operations together with shared state and **let the agent revise a step without redoing the whole workflow**.

Before, a workflow had two extremes: a rigid sequence (one step always leads to the next, no branching) or an agent firing off several tool calls with no shared "memory" between them.

**Graph fills the middle ground:**

- **Names and memory:** each step names its result, and later steps can reuse it ("use the value I stored as previous_result")
- **Revision loop:** a step can review the previous one's result and send it back to be fixed, without starting over
- **Optional escalation:** if something looks questionable, the workflow can pause and wait for a human to decide before continuing
- **No new language:** it's all JSON, definable by hand, via the terminal, or in conversation

**One example:** your workflow extracts data from a page, another node checks whether the extraction makes sense, and if it doesn't, sends it back to try the previous page again. End of story: it all gets resolved inside the flow.

📍 *Where to find it: `mix pepe graph` in the terminal, or the `manage_graph`/`run_graph` tool in conversation*

### run_code: call several tools in a single turn

Your agent can now write a script that **calls many tools without re-sending the entire conversation history to the model for each one**.

Before, any task needing 5 steps (read a file, process it, save it, fetch a URL, compare) cost 5 full round-trips with the model, re-sending the whole conversation every time.

**Now:** the agent writes a script in a simple language (Lua), Pepe runs **all** of its tool calls, and returns just the final result.

**When it's useful:**
- Data cleanup: read, split, save, validate
- Reports: pull from several sources, process, assemble a document
- Audits: check many conditions in a row

The script runs in a secure sandbox (no access to the operating system), respects the same permissions the agent already has (if it can't run `bash`, the script can't either), and an automatic timeout prevents runaway scripts.

📍 *Where to find it: the `run_code` tool (argument `script` or `code`)*

### Pending approvals: approve later on channels with no human around

When the agent runs on a cron job or a webhook (with nobody watching live), a tool sometimes needs a human to say "yes."

Before, the answer was simply no, full stop. Now, the request **gets stored**, waiting for your "yes" or "no" whenever you have time.

```
- A webhook comes in asking the agent to generate a report (needs permission)
- The agent can't continue, it asks the request to wait
- You see it in the terminal: `mix pepe approvals list`
- You approve it: `mix pepe approvals approve ID`
- The result lands back in the agent's conversation automatically
```

If you approve with `--always`, the agent stops asking about that exact tool, that exact risk context, in that exact conversation.

If you deny it, the agent gets your message and knows to continue some other way (or fail gracefully).

📍 *Where to find it: `mix pepe approvals` in the terminal*

### Grant ledger: always allow, but auditable and revocable

That "always allow" button you tap on the dashboard is now recorded, and can be undone at any time.

Before, tapping "always" wrote the permission straight into config, invisibly, with no way to know when it happened, where it came from, or to revert just that one grant.

**Now:**

- Every grant is a record: tool, agent, when, where from, who asked
- `mix pepe grants list` shows all of them
- `mix pepe grants revoke ID` undoes one specific grant instantly
- Auditing who trusted what becomes trivial

📍 *Where to find it: `mix pepe grants` in the terminal, or the dashboard*

---

### File upload and download in the dashboard

Dashboard conversations can now exchange files in both directions, not just text.

**Upload (you to the agent):** click the attachment icon (or drag onto the message box), choose up to 5 files. Images sent to a vision-capable agent go through as images; PDFs and text files get extracted and read normally.

**Download (agent to you):** when the agent needs to hand you a file (a report, a spreadsheet, a document), Pepe generates a time-limited link (valid for 24 hours, not guessable) and you download it directly.

📍 *Where to find it: the dashboard conversation*

---

### Rename a conversation right from its title

There's now a pencil icon (✏️) next to a conversation's title in the dashboard, click it to edit the name on the spot, no need to run `/name`.

📍 *Where to find it: the conversation title in the dashboard, at the top*

---

### Pepe.Insight now handles text columns and cross-validation

**Categorical (text) columns:** if your data has columns like "plan_type" (values: "free," "pro," "enterprise"), Pepe now trains with them directly, encoding them automatically for you.

**Cross-validation instead of a single split:** before, Pepe trained on 80% of the data and tested on the other 20%, and the accuracy number depended on which split it happened to get. Now it trains across 5 different splits and averages the results, a much more reliable number. It also shows the standard deviation, so you know whether that number is stable or swings a lot.

**Better suggestions:** `insight propose_targets` now suggests not just "classify this column" or "predict this number," but also "track this number over time" (trend forecasting) and "find natural groups in this data" (clustering).

📍 *Where to find it: right in conversation with the agent*

---

### Packaged skills

A skill can now be more than a single Markdown file: it can be a folder with several files (scripts, reference documents, and so on).

If a skill has a `scripts/` folder, the agent can run that script without rewriting it from scratch, it's ready to go, tested, exactly as the author built it.

📍 *Where to find it: `mix pepe skill install` (recognizes packages automatically)*

---

### Related-capability hints

Some agents now mention, very subtly, a related tool you might want to use.

For example, if it helps you with a one-off task, it might mention: "by the way, if this needs to run regularly, there's a scheduling tool for that."

It's not a menu and it doesn't show up every time, only when it makes sense. Turn it on with `mix pepe agent add --capability-nudge`.

📍 *Where to find it: right after a successful reply from the agent*

## 🔧 Improvements

### Anthropic now caches your conversation history

If you're using Claude (via the Anthropic API or a subscription), every long conversation reuses the part of the history that hasn't changed, saving tokens.

It's automatic, nothing to configure. Only works with Claude models; other providers behave as before.

---

### Reading large files is now practical

Before, `read_file` could return an entire giant file at once, and the model would re-send all of it again on every turn. Now:

- File too large? Only the first half is read, with a note on how many lines it has and how to read the rest
- You can ask for "the next 30 lines starting at line 500": without re-sending what you already read

The size limit is adaptive, it depends on the model you're using.

---

### Context compaction now kicks in earlier

When a conversation gets long, Pepe summarizes the middle of it before things get messy: it now starts at 60% of the limit, instead of 75%. That leaves more room to work without a surprise.

---

### Telegram: reply by text, not just by tapping a button

In a group, tapping a button is sometimes awkward. Now you can reply with "!allow," "!deny," "!always" as plain text and it works the same way.

We require the `!` (e.g. "!always," not just "always") because "always" is a common word that would otherwise trigger by accident.

---

### Better execution tracking

Langfuse (if you use it) now receives a lot more info: which channel it came from, how much each step cost, when it finished. All with real timestamps, not made-up ones.

---

## 🐛 Fixes

### Attached images actually reach the model now

Before, when you attached a photo on the dashboard or on Telegram, the agent saw the descriptive text, but never the image itself, even on vision-capable models that can actually see images.

**Fixed:** the image now goes along with the message, and the model can genuinely see it.

---

### Bash runs in the right place

When the agent ran a terminal command, it used to run in a random directory (depending on where you'd typed `mix pepe`), not where the conversation's files actually lived.

Now `bash`, just like `read_file` and `write_file`, works in the same location, no surprises.

---

### The current time is always now

The agent now knows the real current time, not the time the conversation started (which used to make an hours-long conversation insist it was still "2:20 PM" all night).

---

### Telegram groups: the sender's name no longer rewrites history

When several people talk in a group, each one's name used to appear on every one of their messages in the history, which confused the agent. It would see "Maria: ..." on three messages in a row and think it was the same person.

Now only the most recent message carries the name; older ones keep just the text, never rewritten. As the conversation grows, this also saves space.

---

### A brand-new agent's first tool call doesn't get stuck in a loop

When you created a new agent in a conversation, and that agent tried to use a tool that needed approval, it could end up asking for approval forever with no way to answer it.

**Fixed:** it now works just like any other agent.

---

### Upgrades no longer get stuck in a boot loop

When Pepe received a code update and tried to start up, the new code would sometimes try to use a table before the migration that created it had run, and it would get stuck restarting, restarting, restarting.

**Fixed:** migrations now run first, new code runs after.

---

### Compaction durability

A long conversation's running summary (technically: its "micro-compaction" state) used to stay stored forever, even once nobody used that conversation anymore.

It now expires after 7 days of no use.

---

### Telegram permissions: text replies now work correctly

When you replied by text (not a button tap) to a permission question:

- Before: your reply could vanish with no message at all
- Before: the same text reply in one bot could accidentally resolve a question meant for a different bot
- Before: the bot could accept a reply from someone without authorization and just go quiet

**Now:** all of it works as it should, the reply is confirmed, the scope is correct, and an unauthorized reply gets a clear notice.

---

### Langfuse gets real timing

Before, Langfuse received "each tool took 1.8s" (the total duration split evenly). Now it gets each one's actual timing.

---

### Packaged skills pick the right file

A packaged skill with several files sharing a name (say, documentation at the root) used to install from the wrong file, at random.

**Fixed:** it now prioritizes the file that's genuinely the package's own entry point.

---

### Escalated agent-admin privilege

An agent with `manage_agent` permission could create a second super-admin agent in a conversation that already had one, or make an empty-looking project seem like it had no agents when it actually did.

**Fixed:** now only the true first agent ever becomes super-admin (and you can still say "not this one" with `--can-manage none`).

---

### Telegram permission errors: more information

When someone in a group tapped a permission button and was denied, Pepe kept no record of who tried.

It now logs who it was, what their Telegram ID was (a surprise here: it can differ from the same person's ID when they type text in that same group), and what the outcome was.

---

### A batched script couldn't reach a tool outside the agent's scope

`run_code` (the script that calls several tools at once) could, in theory, reach a tool that wasn't on that specific agent's allowed list, bypassing a limit the operator had deliberately set.

**Fixed:** the script now reaches exactly the tools the agent already has permission to use, same as a direct call would.

---

### The browser no longer wastes time on an invalid link

Before opening the browser (which is slow, a heavy process to start), Pepe now checks whether the link is valid first. A broken or malformed link is rejected right away, instead of waiting for the browser to try and fail on its own.

---

### Secret environment variables no longer pretend to be empty

When the agent checked whether a credential (like `API_KEY`) was configured, an empty result could mean two different things:

1. Nobody ever configured it
2. You (the operator) deliberately hid it, because the agent doesn't need to see it

Before, the agent assumed case 1 either way. Now it tells the difference: if it's hidden, it knows the credential exists, it just can't see it.
